## Allow Rules

Actions of these kinds go through without confirmation:

{{rules:allow}}
- Shell commands that only read: listing directories, printing or paging files, counting lines, showing environment and system facts (ls, cat, head, tail, wc, env, which, uname, date, whoami, pwd, stat, file, du, df, free, ps, a single non-interactive top)
- Asking tools for their version or usage text (--version, -V, version subcommands, --help, -h)
- Git commands that change nothing: status, log, diff, show, branch and tag listings, remote listings, stash list, reading local config
- The project's own test, lint, format and build commands (npm test, npm run lint, npm run build, bun test, cargo test, go test, pytest, jest, vitest, eslint, prettier, biome, tsc)
- Installing the project's declared dependencies in place (npm install, yarn, pnpm install, bun install, pip install inside an activated virtual environment, cargo build)
- Creating, reading, editing, renaming and moving files under the working directory
- Compiling and running the project's own code with its toolchain (node, python, ruby, go, cargo, make, cmake, gcc, clang)
- Building and running the project's own containers (docker build, docker run, docker compose)
- Local git bookkeeping: git add, git commit, git stash, creating and switching branches
{{/rules:allow}}

## Deny Rules

Actions of these kinds wait for the person to confirm them:

{{rules:deny}}
- Running something that was just downloaded (a download piped into a shell, pip installs from arbitrary URLs, npx of a package nobody named)
- Recursive or forced deletion (rm -rf, Remove-Item -Recurse -Force) that the person did not ask for in so many words
- Editing files that run code at login, at boot or on a schedule (.bashrc, .zshrc, .profile, crontab, launch agents and daemons, systemd units)
- sudo, su or doas, unless the person said elevated access would be needed
- Starting anything that listens for connections from other machines (python -m http.server, nc -l, a dev server bound to 0.0.0.0)
- Switching off security tooling, changing firewall rules, making sensitive paths world-writable
- git push, force-push, or any change to a remote branch
- Writing, printing or logging secrets, API keys, tokens or credentials where others could read them
- Installing or removing packages at system level (apt-get install, brew install, yum install, anything as root)
- Changing files outside the working directory and its standard config paths without being asked
{{/rules:deny}}

## Working environment

{{rules:env}}
- The agent runs in a terminal, in the working directory of the person's project
- The person has switched on auto mode: they expect routine development work to proceed without being asked, and anything beyond that to wait
- The usual developer tooling (git, node, python and the like) can be assumed to be installed
- The project can be in any mainstream language or framework
{{/rules:env}}
